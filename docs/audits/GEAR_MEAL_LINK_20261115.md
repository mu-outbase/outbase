# ダッチオーブン訂正・スキレット・登録ギア連動

## 名称と料理

利用者の訂正に従い、ダッチグリルをダッチオーブンへ変更。既存のtoolキー/recipe ID/保存名は消さず、旧キーを読み替え、生成済み名称は表示時に訂正する。保存済みの原本を一括書き換える処理は行わない。旧キーでの同一承認再試行も重複を作らない。

スキレットをフライパンから独立させ、きのこのバターしょうゆ焼き・ソーセージと豆の温サラダを追加。ダッチオーブンの豆とソーセージのトマト煮も追加し、登録レシピは17件。器具・熱源・調理場所の制約は維持。

## ギア登録と料理

現行ギア登録/編集に「料理での用途」と「取扱説明書で確認した対応熱源」を追加。既存ギアは名前から判別し、未知の製品名も用途を指定すると対応分類に繋がる。「料理に使わない」も指定可能。数量0・削除済みは候補対象外。ケース・専用蓋等を調理器具本体と誤認しない。自動判別が合わない場合は明示用途で補正できる。

料理画面で登録製品を選ぶと、選択製品の用途と対応熱源に一致するレシピを絞る。既知の非対応熱源は汎用の対応確認チェックで上書きできない。登録済みの確認済み熱源を選ぶ場合は、その設定を反映する。機器の適合をアプリが実証したという意味ではない。

献立確定時は登録ギアの実名を持ち物へ反映し、activity_assetsでキャンプとの関連を記録する。製品ID/名前を献立へ保存し、同じ製品を重複追加しない。確定前に最新のギアをtransaction内で再確認し、削除・数量0・用途/熱源の不一致を拒否。献立・食材・買い物・準備・ギア関連は一括保存/巻戻しする。

## 追加・更新時の反映

登録ギアを反映するボタンと、画面復帰/同一画面の再描画で再取得する。料理用ギアの追加・削除・数量0・名前/用途/熱源変更を検出し、自動選択していた器具と製品選択肢を更新。人数・食材メモ・入力中の数量を消さず、確認中の候補は再確認を求める。利用者が明示的に変更した器具チェックを無断で上書きしない。開いていた確定済み献立の詳細も復帰後に維持する。

変更は今後の候補へ反映し、確定済みの献立・準備・使用製品名のスナップショットは変更/削除しない。対応は登録済み分類とレシピに基づき、未知の器具から新レシピを自動生成するものではない。

## 検証

Node97件、構文とSW資材検査成功。Pixel7エミュレーションの独立領域で、実際のギア登録フォームから任意名のスキレットと対応熱源を保存し、別タブからの反映、料理/数量の入力保持、製品選択、非対応熱源の拒否、最新ギアの再確認を検証。

ギア関連の書込失敗で全件巻戻し、オフライン保存、登録製品名の準備反映/関連1件、数量0・用途変更・削除で今後の選択肢更新、確定済み献立/製品名/持ち物履歴の保持と同一リクエスト再試行を確認。ギア編集フォームでもPWA更新の再読込を保留。旧ダッチグリルのID/条件/名前を持つ原本の保持と承認再試行も確認。

既存の料理条件・購入状態・準備共有、機器別候補と場所制約、既存カレンダー、PWA更新時の記録/Blob保持・連続更新・オフラインも回帰成功。Android実機と実際の調理実証は含まない。MVP完成判定は引き続き保留。
