# 予定名からキャンプ場を探して選択

場所未設定のキャンプ予定で予定名を初期検索語とし、HOMEの「予定の天気見立て」に候補を自動表示する。利用者は検索語を編集でき、候補は施設名と地名・住所で区別する。キャンプ場を優先して並べるが、予定への保存は候補を押すまで行わない。既に座標を保存している場合はその選択を維持し、必要時に場所確認を開いて変更する。

既存のPhoton地点検索が指定していたlang=jaは実APIで400（対応はdefault/de/en/fr）となることを確認し、候補検索・既存地点検索ともlang=defaultへ修正した。実際の「朝霧ジャンボ, 日本」検索で200、朝霧ジャンボリーオートキャンプ場とゴルフ倶楽部の2候補を確認した。新しい外部APIは追加しない。

選択した名称・住所・緯度経度・取得元・選択日時を保存し、予報は保存座標を使う。ネイティブカレンダーは元の予定IDを保ち、他の予定とメモ・色・参加者・繰り返しを保持する。Story活動はトランザクション中の最新行を読み、状態・記録・メタデータとカレンダー関連を保持する。対象の削除やタイトル・場所の変更を検出したら保存せず再選択を案内する。座標が変わったら旧地点の予報は使い回さない。

検索中に画面が描画され直しても状態を引き継ぎ、別予定へ移った後の遅い応答は反映しない。進行中の天気取得中に候補が選ばれた場合は、完了後に選択地点の更新を一度予約する。検索失敗・候補なし・容量不足を表示し、保存していない場所を保存済みと表示しない。

検証: Pixel 7で予定名から複数候補、住所による識別、選択前に書き込みなし、容量不足で原本保持、2番目の候補の座標と予報への反映、再読み込み後の維持、候補なし・通信失敗、Story活動の元データ保持を確認（地点と予報は制御fixture）。位置選択・候補順位・API対応言語・旧地点予報の排除など単体11件、既存カレンダーとGate2 26/26、入力保持・PWA更新時の下書き維持・旧版更新とオフライン起動も成功。Android実機は未確認。
