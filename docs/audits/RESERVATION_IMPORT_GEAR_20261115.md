# 現shellの予約本文取込とギア保存確認

予定追加画面に予約本文の取込を接続。候補抽出・プレビュー・入力欄への反映では書き込まない。年のない日付・不正日付・不明時刻は空欄で確認を求め、予約日や決済日を滞在開始日に使わない。入力欄で予定名・日程・場所を修正し、準備候補を選んでから保存する。画像/PDF/OCR読取ではなく、本文貼付のみ。本文は既存の端末内IndexedDBに保存し、解析目的の外部送信は行わない。

承認は活動・カレンダー・選択した準備項目を同一transactionで保存する。リクエストIDで同一操作の二重送信・保存後の再試行を重複作成しない。異なる内容で同じIDを再利用した場合は拒否。別の取込操作を始めて同じ予約本文を再登録することまで自動判別するものではない。元の通常の予定編集保存経路は維持する。

準備候補は予約確認・テント/寝具/照明・献立/食材確認・前回反省の確認。コタ用品は明示的な同行選択で追加する。不要な候補は除外でき、同行の切替でも既に除外した他分類の選択状態を保持する。予約情報だけでは具体的な必要量や天候条件を決められないため、これで全準備生成が完成したとは扱わない。

ギア登録は現shellの名前・分類・数量・保管場所・メモの追加/編集/削除を確認。数量0が1へ変わる既存不具合を修正した。

## 現在の機能区分

- ギア登録: 現shellに保存/再表示/編集/論理削除がある。本試験で確認。
- 料理相談: 旧prepEngineに献立案、旧Chappy UIに外部相談用プロンプト受渡しコードがある。現shellには料理分類への手入力追加があるが、対話相談→献立承認→食材/買い物確定の導線は接続していない。
- サイト探索（利用者の定義）: キャンプ場内を散歩し、各区画サイト・炊事場・トイレなどの場所と特徴を記録し、後から見返す機能。旧src/modules/walk/walk.jsにcampWalk（場内探索）がある。現shellにはGPS・汎用の場所ピン・写真・メモの保存があるが、区画番号や設備分類を付けてキャンプ場内の記録を一覧・地図で見返す専用導線は未接続。キャンプ場検索・比較・空き検索という以前の解釈は誤り。
