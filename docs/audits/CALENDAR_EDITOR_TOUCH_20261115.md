# カレンダー入力中の意図しない閉じ操作

予定登録画面のsheet全体で下向きタッチ移動を監視し、90px以上でclose()していた。入力欄や日付・メモの操作から始まる指の移動まで閉じる操作として扱っていた。Pixel 7エミュレーションのカレンダーiframe内で、入力欄を対象に130pxの下向きTouchEventを送り、入力済みの窓が消えることを修正前に再現。

開始箇所を上部のつまみ・見出しに限定し、ボタン・入力・リンクは除外。複数タッチ、横方向移動、touchcancelでは閉じ操作を取り消す。保存と明示的な閉じボタンの処理は維持。

修正後は同じ入力操作で窓とタイトル・メモを保持。中断したヘッダージェスチャーも閉じない。そのまま保存し一件だけ登録され、再読み込み後も内容が残ること、明示的に閉じた新規予定は追加されないことを確認。既存Story/calendar連携とGate2 26/26、構文、SW資材の整合確認も成功。

iframe HTMLと実際のカレンダーJSに新しいURLを付け、起動資材・SWのURLも更新。カレンダーHTMLの全script URLがSWにあることを既存資材テストに追加。検証は使い捨てブラウザと合成TouchEventで、利用者の端末データには触れていない。
