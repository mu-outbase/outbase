# 現行画面の料理相談・献立

## 今回の機能

キャンプ予定詳細・詳細な準備・既存カレンダーのキャンプ予定から「料理相談・献立」を開ける。人数、調理時間、日付/朝昼夕/追加の一品、手持ち食材、使わない食材、火を使わない条件、今回使う器具を指定し、登録レシピ7件から合う候補を絞る。

これは登録レシピの条件検索と献立計画であり、AIとの自由な対話や新しいレシピの自動生成ではない。画面にも登録レシピからの候補と明記。候補に一致する器具は登録ギアから初期選択するが、利用者が今回使える物に修正する。数量0や削除済みのギアは初期選択しない。

人数から食材量の目安を算出し、選んだ料理の数量と買う/持参するを確認してから保存する。手持ち食材は候補の優先に使い、十分な量があるとは自動判断しない。「買う」を外した食材は持参項目へ、必要器具は持ち物へ、買う食材は買い物へ追加する。器具の同名項目は既存の準備と重複追加しない。食材は日付/食事ごとに保持し、別の料理の量を自動合算して既存購入済み数量を書き換えない。

献立・食材・買い物リスト/項目・準備を同じtransactionで保存。候補確認だけでは書込なし。失敗時は全部巻き戻し、確認画面の選択や数量を保持する。同一保存要求の二重操作・再試行は重複作成せず、内容が違う同じ要求IDは拒否。条件を変更すると確認中の候補を無効にして再検索を求める。保存後の読取失敗は保存失敗と区別する。

確定した献立は再読み込み/オフラインで見返せる。準備の買い物をチェックすると対応するshopping_itemsも購入済みにし、取り消すと両方未完了に戻す。準備共有にも日付・食事・食材数量・持参食材・器具が入る。保存後は準備のキャッシュを破棄し、元の準備画面に戻ると即座に新しい項目を表示する。

既存v44カレンダーは変更しない。初めて承認するときだけ内部のキャンプ保存先も一括作成し、失敗時はその作成も巻き戻す。場内探索と同じ保存先を共用し、通常の予定やカレンダーに二重表示しない。キャンプの日付範囲外の献立は確定しない。既存イベントの元メモ・参加者を保持する。

## 検証

Node86件、構文検査、SW実資材の網羅・重複なし確認成功。Pixel7エミュレーションの独立保存領域で以下を確認:

- 人数と数量、器具/時間/火を使わない/指定食材による絞込、手持ちによる優先、登録ギアの数量0/削除済み除外。
- 候補段階で書込なし、数量修正・持参指定・再描画/PWA更新時の入力保持。
- 買い物書込失敗時の全巻戻し、確認内容の保持、オフライン確定、二重送信/再試行、再読込。
- 最終日の朝食を含む複数日程、条件変更で候補無効化、器具の重複なし、全食材持参なら買い物を増やさない、期間外拒否。
- 献立/食材/器具/持参食材の準備・共有、購入済みと準備チェックの相互状態維持、親予定の内容不変。
- 既存カレンダー入口、承認前は内部保存先も作らない、失敗時に内部保存先も巻戻し、元イベント不変、場内探索と保存先共用、予定二重表示なし。

既存の準備共有、改善→次回準備、場内探索、PWA更新時の記録/Blob保持・連続更新・オフライン起動も回帰確認成功。実機Androidのキーボード/共有先確認は含まない。自由なAI料理相談、料理レシピの追加編集、複数料理をまたぐ食材の数量集計は今後の作業。MVP全体の完成判定は保留。
